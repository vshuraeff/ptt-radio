# ptt-radio: дизайн PTT-прототипа

Голосовая рация для мультиплеера Factorio 2.1.23. Голос идёт через сам мультиплеер игры с помощью Lua UDP API, без отдельного голосового сервера. Состоит из двух частей: мод `ptt-radio` (чистый Lua, ставится всем) и программа-компаньон у каждого игрока, который хочет говорить и слышать. Игрок без компаньона и без флага `--enable-lua-udp` играет как обычно и видит плашки, но голоса не слышит.

Все цифры задержки ниже измерены на одной машине (клиент macOS и headless-сервер в OrbStack), см. `../udp-probe/README.md`. Реальная сеть добавляет к ним пинг.

## Свойства транспорта, на которых строится дизайн

Пакет компаньона попадает в игру через `helpers.recv_udp()`, становится input action и через lockstep-мультиплеер приходит на все пиры как `on_udp_packet_received` с `player_index`, который проставляет движок. Отсюда следует:

- **Потерь и перестановок нет по построению.** Input actions доставляются надёжно и по порядку. Пробник это подтвердил: 0 потерь и 0 перестановок на 15 000+ пакетах. Поэтому in-band FEC и PLC не нужны, а DTX в режиме PTT бесполезен. Здесь рекомендации Opus из отчёта `reports/Голосовая рация для Factorio.md` (FEC 5–10 %) отменяются.
- **Единственный режим отказа — пачка после задержки.** При автосохранении пакеты копятся и приходят разом: RTT подскакивает со 116 мс до ~600 мс. Пауза игры даёт то же самое. Значит, буфер на приёме нужен для сброса опоздавших кадров, а не для маскировки потерь.
- **Пакеты приходят пачками по тику**, с интервалом 16,7 или 33 мс. Глубина буфера 40–60 мс это покрывает.
- **Отправителя определяет движок.** Подделать «кто говорит» нельзя: мод берёт `event.player_index`, а не поле из пакета.
- **Весь голос получают все клиенты**, включая тех, у кого нет компаньона. Мод решает только, каким локальным компаньонам переслать пакет через `send_udp`. На сетевую стоимость он не влияет.
- **Экземпляр без флага не ломается.** `recv_udp` и `send_udp` там ничего не делают. Проверено в обе стороны.

## Мод `ptt-radio` (Lua)

### Состояние только по тикам

У мода нет часов, и он не должен их имитировать. Любые таймауты считаются через `game.tick`. Во время сохранения и паузы тики стоят, поэтому таймаут не сработает ложно на измеренной задержке в 600 мс.

- `storage.speakers[player_index] = last_tick`: выставляется на `START` и на каждом `VOICE`, снимается на `END`.
- `script.on_nth_tick(15)` снимает говорящего, если `game.tick - last_tick > 30` (0,5 с игрового времени), и рассылает слушателям синтетический STOP. Это страховка на случай, если компаньон упал посреди передачи: без неё у слушателей зависло бы воспроизведение. Замерено: STOP приходит через ~590 мс после последнего кадра.

### Обработка пакета

```lua
script.on_event(defines.events.on_tick, function() helpers.recv_udp() end)

script.on_event(defines.events.on_udp_packet_received, function(e)
  -- e.player_index: чья копия игры приняла пакет; 0 = сервер
  local magic, version, kind = string.byte(e.payload, 1, 3)
  if magic ~= 0x52 or version ~= 1 then return end
  -- HELLO: ответить ростером только этому компаньону
  -- START / VOICE / END: обновить storage.speakers, плашку и звук, затем fan_out
end)
```

`fan_out(sender, payload)` для каждого `q` из `game.connected_players` вызывает `helpers.send_udp(port_q, header(sender) .. body, q.index)`. Отправитель исключается, если у него не включён эхо-режим. `port_q` берётся из per-user настройки `ptt-radio-companion-port` (по умолчанию 34555). Настройки игроков синхронизированы, так что это детерминированно. Каждая машина фактически отправляет только одну копию, своему компаньону.

Область вещания задаёт map-настройка `ptt-radio-scope`: `all` (по умолчанию) или `force` (только своя команда). Это тоже локальный фильтр в `fan_out`.

### Плашка, звуки, клавиши

- **Плашка.** Фрейм в `player.gui.screen` у каждого игрока, по одному `label` на говорящего, `style.font_color = speaker.color`. Перестраивается только из событий: смена набора говорящих, `on_player_joined_game`, `on_player_left_game`, `on_player_color_changed` (новое в 2.1). Себя тоже показывает, как в Dota. Говорящий с `player_index == 0` выводится как «Сервер»: так эмулятор на стороне Docker может проверять плашку, пока второго клиента нет.
- **Щелчок рации.** `player.play_sound` на `START` и `END` у слушателей, без участия компаньона. Звуки задаются в `data.lua` как `SoundPrototype`. В v0.1 можно взять встроенные пути `utility/...`, свои `.ogg` добавить позже.
- **Переключатель открытого микрофона.** `custom-input` `ptt-radio-toggle-mic` → мод → `send_udp(port, TOGGLE, player_index)` своему компаньону. Удержание PTT ловит компаньон, потому что `custom-input` не сообщает об отпускании.
- **Запасной путь удержания на чистом Lua (не в v0.1).** Selection-tool с `send_pre_selection_events`: `on_player_start_selected_area` срабатывает на нажатие ЛКМ, `on_player_selected_area` на отпускание. Пригодится на Wayland, где глобальной клавиши может не быть. Документация предупреждает, что эти события стоят производительности в мультиплеере, поэтому включается только по выбору.

## Формат пакетов

Lua 5.2 в Factorio не имеет `string.pack`, поэтому заголовок фиксированный и разбирается через `string.byte` и `string.char`. Тело для мода непрозрачно: двоичные Opus-кадры с `\0` проходят без искажений (проверено).

Компаньон → игра (`127.0.0.1:<порт --enable-lua-udp>`):

| Байты | Поле |
|---|---|
| 0 | `0x52` (`R`) |
| 1 | версия протокола, `1` |
| 2 | тип: `0x01` HELLO, `0x02` START, `0x03` VOICE, `0x04` END |
| 3–4 | номер кадра, u16 big-endian (для VOICE; в START/END — номер последнего) |
| 5… | тело: Opus-кадр для VOICE, версия компаньона для HELLO |

Игра → компаньон (`127.0.0.1:<ptt-radio-companion-port>`): тот же заголовок, после байта типа вставлен `sender_index` u16 big-endian. Типы ответа: `0x02`/`0x03`/`0x04` пересланные, `0x10` ROSTER (строки `index\tname\tr,g,b`), `0x11` TOGGLE.

Один Opus-кадр по 20 мс на пакет. Пакеты всё равно приходят пачками по тику, поэтому объединять кадры имеет смысл только после замера накладных расходов на input action.

## Компаньон

Язык: Rust, один бинарник. Потоки: глобальная клавиша, захват (callback `cpal` → кольцевой буфер), кодер, UDP-сокет `127.0.0.1:34555`, декодер и микшер → вывод `cpal`.

### Передача

- 48 кГц моно, кадр 20 мс (960 сэмплов), Opus `VOIP`, 16 кбит/с по умолчанию: для рации хватает, и это меньше нагрузки на всех клиентов. FEC и DTX выключены.
- По нажатию PTT: `START`, затем 100–150 мс уже записанного звука (pre-roll, 5–7 кадров разом), затем поток `VOICE`.
- По отпусканию: дописать текущий кадр, отправить `END` дважды. Мгновенную тишину даёт сам компаньон: после отпускания он перестаёт отправлять кадры, а слушатель по `END` сразу останавливает воспроизведение.
- Порт игры (`--enable-lua-udp`) берётся из конфигурации компаньона: из игры его узнать нельзя. Связь проверяется пакетом HELLO: если ROSTER не пришёл за 2 с, игра не запущена с флагом или не в мультиплеере.

### Приём

- Отдельная очередь на каждого говорящего. Воспроизведение начинается, когда накопилось 40 мс или прошло 60 мс после `START`.
- Если в очереди больше 200 мс (пачка после автосохранения), лишнее выбрасывается до целевой глубины. Догонять, проигрывая подряд, нельзя.
- По `END` доиграть остаток и закрыть поток. При опустошении очереди посреди передачи вставляется тишина: потерь нет, только неравномерность.
- Микшер: сумма потоков с громкостью на игрока (по ROSTER), мягкое ограничение. Опционально «эффект рации»: полоса 300–3400 Гц.
- **Эхо-режим.** Мод пересылает пакет и самому отправителю. Это проверка всего тракта (микрофон → Opus → сервер → декодер → динамик) на одной лицензии.

### Клавиша и права ОС

- **macOS (первая платформа).** `global-hotkey` сообщает `HotKeyState::Pressed` и `Released`. Захват микрофона требует `NSMicrophoneUsageDescription`, а в подписанной сборке ещё и entitlement `com.apple.security.device.audio-input`. Мышиные кнопки как PTT требуют `CGEventTap` и права Input Monitoring. Непроверенное: что `global-hotkey` на macOS обходится без Input Monitoring, и что неподписанная сборка, запущенная из терминала, наследует права терминала.
- **Windows.** `global-hotkey` или `WH_KEYBOARD_LL`.
- **Linux.** X11 через `global-hotkey`. На Wayland нужен портал GlobalShortcuts (`Activated`/`Deactivated`) или запасной путь через selection-tool в моде.

## Нагрузка и задержка

Трафик (вывод, накладные расходы input action не замерены): ~40 Б Opus + 6 Б заголовка на кадр, 50 кадров/с, то есть около 3 КБ/с на говорящего с запасом. Исходящий канал сервера составляет примерно `N клиентов × S говорящих × 3 КБ/с`. При 10 клиентах и 3 одновременных говорящих это ~90 КБ/с, или ~0,7 Мбит/с. Клиенты без компаньона скачивают то же самое. Пробник выдержал 500 пакетов/с по 120 Б с одного клиента без потерь (RTT p50 134 мс).

Задержка «рот–ухо» (оценка):

- Измеренный транспорт «клиент → сервер → клиент»: p50 93–116 мс на localhost.
- К нему прибавляются кадр 20 мс, lookahead Opus ~5 мс, буфер на приёме 40–60 мс и вывод ~10–20 мс.
- Итого ~170–210 мс на одной машине, в реальной сети ещё пинг до сервера у обоих игроков. Это хуже, чем у Discord (~100 мс), но для рации приемлемо.

Число 110–150 мс в предыдущем ответе не учитывало буфер на приёме и было занижено.

## Ограничения

- Пауза игры (админом или `auto_pause_when_players_connect` при подключении игрока) и автосохранение останавливают голос: input actions на паузе не обрабатываются, `recv_udp` не вызывается. Пакеты копятся в буфере сокета на 256 КБ (около 85 с речи одного говорящего), после паузы приходят пачкой и выбрасываются компаньоном как устаревшие; при более долгой паузе лишнее теряется. Это по документации, на стенде замерено только автосохранение. Голос на паузе возможен лишь через отдельный ретранслятор, не связанный с тиками.
- Каждому игроку нужен флаг `--enable-lua-udp <порт>`: в Steam через параметры запуска, у standalone-версии компаньон может запускать игру сам.
- Мод можно выложить на портал. Исполняемые файлы портал, по словам авторов модов, не принимает, поэтому компаньон распространяется через GitHub Releases.
- Любой локальный процесс может писать в Lua UDP-сокет игрока. Это допустимо: он может говорить только от имени этого же игрока.
- Голос получают все клиенты, независимо от `ptt-radio-scope`. Фильтр по команде скрывает голос, но не экономит трафик.
