# Компаньон

Прочитав эту страницу, вы запустите компаньон рядом с игрой, с выбранными вами микрофоном и динамиками, и узнаете, как говорить: удерживая клавишу рации или через открытый микрофон.

Компаньон — консольная программа. С игрой он общается по UDP через `127.0.0.1`, поэтому запускать его нужно на том же компьютере, что и игру. Пока вы играете, он работает; закрыть его можно сочетанием `Ctrl-C`.

## Первый запуск

1. Сделайте нужные микрофон и динамики (или наушники) устройствами ввода и вывода **по умолчанию** в системе (см. [Устройства](#устройства)).
2. Откройте терминал в папке, куда распаковали компаньон (на Windows — «Командную строку» или PowerShell).
3. Запустите:
   - Windows: `.\ptt-radio-companion.exe` (в PowerShell `.\` обязателен, в «Командной строке» тоже работает)
   - macOS и Linux: `./ptt-radio-companion`
4. Среди первых строк будут такие:

   ```text
   ptt-radio-companion 0.4.0 (libopus 1.6.1, static), listening on 127.0.0.1:34555, game at 127.0.0.1:34556
   push-to-talk key: F8
   ```

5. Запустите Factorio с `--enable-lua-udp 34556` (см. [Установка](RU-Installation)) и зайдите в сетевую игру. В чате появится `Рация: компаньон подключён.`, а компаньон выведет список игроков.
6. Зажмите `F8`, скажите что-нибудь, отпустите. Компаньон напишет `ptt pressed` и `ptt released`.

Чтобы услышать себя, включите настройку мода для игрока «Эхо своего голоса»: сервер будет возвращать вам ваш же голос, и весь путь звука можно проверить в одиночку.

## Параметры

Параметры, которые могут понадобиться игроку:

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| `--game-port <ПОРТ>` | `34556` | Lua UDP-порт игры, то есть число после `--enable-lua-udp`. |
| `--port <ПОРТ>` | `34555` | Порт, который слушает компаньон. Должен совпадать с настройкой мода для игрока «Порт компаньона». |
| `--ptt-key <КЛАВИША>` | `F8` | Клавиша рации, например `F8`, `F13`, `shift+F8`, `ctrl+alt+F9` (подробнее ниже). С `none` клавиша не регистрируется, и работает только открытый микрофон. |
| `--hub <IP:ПОРТ>` | нет | Хаб рядом с сервером, если он там есть (см. [Хаб](RU-Hub)). Только IP-адрес с портом, не имя хоста. |
| `--game-only` | выкл. | Голос идёт только через игру, собственных голосовых маршрутов компаньон не открывает. |
| `--aec on\|off` | `on` | Обнаружение и подавление эха. С `on` обнаружение работает всегда, а подавление обрабатывает звук микрофона, только пока компаньон слышит в нём ваши динамики. С `off` нет ни того, ни другого (см. [Эхо](#эхо-и-полудуплекс)). |
| `--bitrate <БИТ/С>` | `16000` | Битрейт Opus. |
| `--no-playback` | выкл. | Не открывать устройство вывода: вы говорите, но ничего не слышите. |
| `--record-received <ФАЙЛ.wav>` | нет | Дополнительно записывать всё, что вы слышите, в WAV-файл. |
| `--udp-bind <АДРЕС>` | интерфейсы маршрута по умолчанию | Локальный сетевой интерфейс и порт для прямых соединений (можно указать до четырёх раз). |
| `--stun-server <ХОСТ:ПОРТ>` | `stun.l.google.com:19302` | Публичный STUN-сервер, через который компаньон узнаёт свой внешний адрес. Чтобы указать несколько, повторите параметр. Указанные серверы заменяют сервер по умолчанию, а не добавляются к нему. Используется не больше четырёх адресов, и имя хоста, за которым стоит несколько адресов, занимает несколько из этих четырёх мест. С `--game-only` STUN не используется вовсе. |
| `--no-self-update` | выкл. | Не проверять новый релиз при запуске (см. [Обновления](#обновления)). |
| `--no-self-uninstall` | выкл. | Не удалять установленный компаньон, когда удалён мод (см. [Удаление вместе с модом](#удаление-вместе-с-модом)). |
| `--launch <КОМАНДА ИГРЫ...>` | нет | Запустить игру и работать, пока она работает (см. [Запуск игры через компаньон](#запуск-игры-через-компаньон)). Ставится последним. |

Полный список вместе с тестовыми параметрами выводит `ptt-radio-companion --help`.

В `--ptt-key` указывается одна основная клавиша; перед ней через `+` можно добавить модификаторы: `shift`, `ctrl` (или `control`), `alt` (или `option`) и `cmd` (или `command`, `super`, `meta`). Регистр в названиях клавиш и модификаторов не важен, но `none` пишется только строчными буквами: `None` компаньон примет за название клавиши и не распознает. Если название клавиши не распознано, указаны две основные клавиши или модификатор стоит после клавиши, компаньон останавливается с `error: --ptt-key <КЛАВИША>: ...`; с `--launch` игра всё равно запустится, но без компаньона. Если же клавиша записана правильно, но система её не даёт (например, её уже заняла другая программа), компаньон только выводит предупреждение и продолжает работать, а говорить можно лишь через открытый микрофон.

### Два игрока на одном компьютере

Каждой копии игры нужна своя пара портов. Для второго игрока:

1. Запустите вторую игру с другим портом, например `--enable-lua-udp 34566`.
2. В этой игре поставьте в настройке мода «Порт компаньона» значение `34565`.
3. Второй компаньон запустите с `--game-port 34566 --port 34565` и другой клавишей, например `--ptt-key F9`: одну клавишу нельзя зарегистрировать дважды. С `--ptt-key none` этот игрок говорит через открытый микрофон.

## Обновления

Компаньон со страницы релизов обновляется сам:

1. При каждом запуске он спрашивает у GitHub, какой релиз проекта последний.
2. Если этот релиз новее запущенной версии, компаньон скачивает архив для вашей системы и сверяет его с `SHA256SUMS` этого релиза.
3. Затем заменяет свой файл программы новым и перезапускается с теми же параметрами. Заменяется только компаньон, мод он не трогает.

Обновляется он только на более новую стабильную версию, на старую или ту же — никогда. При каждом запуске компаньон пишет ровно одну строку `self-update: ...`, даже если всё прошло гладко: `up to date (...)`, `updated to <версия>` (её пишет уже перезапущенная новая версия), `disabled (opted out)`, `disabled (not a release build)` или причину, по которой проверка не удалась (нет интернета, GitHub не отвечает, контрольная сумма не сошлась, нет права записи в папку). Неудачная проверка компаньон не останавливает: он работает дальше на текущей версии. См. [Если не работает](RU-Troubleshooting#сообщения-self-update).

Проверка идёт до того, как компаньон откроет свой порт, а с `--launch` — до запуска игры, поэтому игра стартует позже. Если обновления нет, это несколько секунд: ответа о последнем релизе компаньон ждёт не дольше 5 секунд. Если обновление скачивается, задержка может дойти примерно до двух минут.

Чтобы отключить обновления, запускайте компаньон с `--no-self-update` или задайте переменную окружения `PTT_RADIO_NO_SELF_UPDATE=1` (подойдёт любое значение, кроме пустого и `0`). Проверять реже нельзя: компаньон проверяет обновления либо при каждом запуске, либо никогда.

Компаньон, собранный вами через `cargo build`, сам не обновляется никогда и пишет `self-update: disabled (not a release build)`.

## Запуск игры через компаньон

С `--launch` компаньон сам запускает игру. Всё, что стоит после `--launch`, — командная строка игры, поэтому собственные параметры компаньона пишите перед ним. Если в командной строке игры нет флага `--enable-lua-udp`, компаньон добавляет его со своим `--game-port`. Компаньон работает, пока работает игра; когда она закрывается, он заканчивает текущую передачу, останавливается и выходит с тем же кодом завершения, что и игра. Если этот код не укладывается в 0–255 (например, код аварийного завершения на Windows), игру завершили принудительно или компаньон не смог следить за её процессом, он выходит с кодом 1.

Если компаньон не смог подготовиться к работе ещё до запуска игры — например, его порт уже занят другим компаньоном, в `--ptt-key` неверное название клавиши или в системе нет устройства вывода, — он пишет `error: ...`, затем `--launch: starting the game without the companion` и запускает игру без себя. В игре вы увидите только сообщение «Рация: компаньон не найден». Если не запускается сама игра, компаньон пишет `error: --launch: cannot start <программа>: ...` и выходит с ошибкой. Второй раз игру он не запускает никогда: если что-то сломалось уже после попытки её запустить, он пишет `error: ...` и выходит с ошибкой.

В Steam откройте «Свойства» игры и в поле «Параметры запуска» вставьте то, что установщик напечатал после `Steam launch options:`. Строка выглядит так, только вместо `<папка данных Factorio>` в ней стоит папка пользовательских данных Factorio, а на Windows в конце — `ptt-radio-companion.exe`:

```text
"<папка данных Factorio>/ptt-radio-companion/ptt-radio-companion" --launch %command%
```

Steam подставит вместо `%command%` командную строку самой игры. Остальные параметры компаньона ставьте перед `--launch`, например `--hub 203.0.113.10:34560 --launch %command%`. Если при запуске нашлось обновление, компаньон сначала устанавливает его и только потом запускает игру; перезапущенный компаньон сохраняет `--launch` и командную строку игры.

## Удаление вместе с модом

Компаньон, поставленный установщиком, лежит в папке `ptt-radio-companion` внутри папки пользовательских данных Factorio, рядом с файлом `install.json`. В этом файле записана папка модов: та, что передана установщику через `--mods-dir` (на Windows — `-ModsDir`), а если её не указали — `mods` внутри папки пользовательских данных Factorio. Папка данных берётся стандартная для вашей системы, если установщику не передали `--factorio-dir` (`-FactorioDir`). Сам установщик папку модов не ищет. При каждом запуске, после проверки обновления, а с `--launch` ещё и после выхода из игры, компаньон ищет в этой папке модов мод `ptt-radio`: любой файл, папку или ссылку с именем ровно `ptt-radio` или начинающимся с `ptt-radio_`. Ни версия, ни расширение `.zip` не проверяются, поэтому забытая в папке старая версия, например `ptt-radio_0.3.0.zip`, тоже считается модом, и компаньон остаётся.

Чтобы удалить себя, компаньон должен хотя бы раз увидеть мод установленным. Первая проверка, которая находит мод, создаёт пустой файл `mod-seen` рядом с `install.json`. До этого отсутствие мода значит лишь, что его ещё не поставили (например, игра скачает его при входе на сервер), и компаньон остаётся. Когда `mod-seen` уже есть, проверка, которая находит папку модов с `mod-list.json`, но без мода `ptt-radio`, удаляет папку компаньона; он пишет одну строку `self-uninstall: ...` и завершается. С `--launch` игра в этот раз всё равно запускается, уже без компаньона. Если заново поставить компаньон установщиком, папка создаётся с нуля, без `mod-seen`.

Если хоть что-то неясно, он ничего не удаляет:

- нет `install.json` — так бывает у компаньона, который вы распаковали или собрали сами;
- `install.json` не читается или записан не установщиком;
- папки модов нет, она не читается или в ней нет `mod-list.json` — тогда компаньон пишет предупреждение;
- установщику указали другую папку модов, не стандартную;
- папка, где лежит программа, называется не `ptt-radio-companion` — например, вы её переименовали или перенесли программу из неё.

Удаляется только его собственная папка, никогда не папка пользовательских данных и ничего другого в ней. Чтобы оставить компаньон и без мода, запускайте его с `--no-self-uninstall` или задайте `PTT_RADIO_NO_SELF_UNINSTALL=1`. После удаления уберите и параметр запуска в Steam: он указывает на программу, которой больше нет.

## Устройства

Выбрать устройство в самом компаньоне нельзя. При запуске он открывает устройство вывода, выбранное в системе **по умолчанию**. Если такого устройства нет, компаньон останавливается с `error: no default output device` (при другой ошибке открытия устройства вывода — так же, только с её текстом); с `--launch` игра запускается без него. С `--no-playback` устройство вывода не открывается вовсе. Микрофон остаётся закрытым, пока игра не разрешит передачу, и закрывается, когда рация выключена, когда вас заглушили или передача вам запрещена либо когда игра целую минуту не подтверждает разрешение. На macOS при выключении рации индикатор микрофона гаснет. Если просто отпустить клавишу рации, микрофон не закрывается: он продолжает записывать — для обнаружения эха и для предзаписи, последних 120 мс перед выходом в эфир, которые уходят в начале следующей передачи.

Подключение игрока, автосохранение или догоняющая синхронизация не закрывают микрофон, если пауза короче минуты; голос по уже установленным прямым маршрутам и через хаб может идти, пока игра заморожена. После выхода из игры индикатор микрофона может гореть ещё до минуты. Микрофон снова откроется, когда игра в следующий раз подтвердит разрешение на передачу. Если микрофона нет или он не открывается, компаньон не останавливается: он пишет `mic open failed: ...; retrying in 1 s` и пробует снова раз в секунду, пока передача разрешена.

- Windows: «Параметры → Система → Звук», там выберите ввод и вывод.
- macOS: «Системные настройки → Звук», вкладки «Выход» и «Вход».
- Linux: настройки звука вашего рабочего стола, либо `pavucontrol` / `wpctl` под PipeWire.

Сменив микрофон по умолчанию в системе, выключите и включите рацию: при каждом открытии компаньон заново берёт текущий системный микрофон. Чтобы сменить устройство вывода, перезапустите компаньон.

Лучше всего играть в наушниках. С динамиками микрофон ловит голоса других игроков, и компаньону приходится подавлять это эхо (см. [Эхо и полудуплекс](#эхо-и-полудуплекс)).

## Как говорить

Передавать можно двумя способами.

**Клавиша рации (PTT).** Держите `F8` (или клавишу из `--ptt-key`) и говорите. Клавиша глобальная: компаньон видит её, в каком бы окне вы ни были, а другим программам она, пока компаньон запущен, не достаётся. Поэтому по умолчанию стоит функциональная клавиша, которой никто не печатает, а не буква.

**Открытый микрофон.** Компаньон передаёт без перерыва. Включить или выключить его можно в игре клавишей `ALT + V` (в настройках управления это действие называется «Открытый микрофон вкл/выкл») или кнопкой «Открытый микрофон» на панели ярлыков. Компаньон пишет `open mic on (you are player N)` или `open mic off ...`. Если компаньон перестанет отвечать, открытый микрофон выключится сам.

`ALT + SHIFT + V` открывает окно «Настройки рации», где выбирается канал (см. [Каналы и администрирование](RU-Channels-and-Admin)). Обе клавиши можно переназначить в настройках управления игры.

## Эхо и полудуплекс

- **Полудуплекс** (настройка мода для игрока «Глушить эфир, пока говорю», по умолчанию включена). Пока вы держите клавишу рации, голоса других игроков не звучат, и динамикам нечего вернуть в микрофон. В наушниках настройку можно выключить. На открытый микрофон она не действует.
- **Обнаружение эха.** Если микрофон слышит ваши динамики, игра покажет панель «Микрофон слышит динамики: наденьте наушники или выключите открытый микрофон» с кнопкой, которая выключает открытый микрофон. Остальные увидят у вашего ника красную метку «эхо». Если эхо тихое, на его обнаружение может уйти несколько десятков секунд. Обнаружение работает только с `--aec on` (так по умолчанию): с `--aec off` ни панели, ни метки не будет.

## Проверка рации

Кнопка «Проверить микрофон и возврат через игру» в разделе «Компаньон» окна «Настройки рации» проверяет весь путь звука через игру:

1. Компаньон проигрывает через динамики короткий проверочный тон, полсекунды. В эфир тон не уходит.
2. Затем он записывает 3 секунды с микрофона — скажите что-нибудь. Рации должна быть разрешена передача, как и для разговора по клавише рации.
3. Запись уходит через игру одной передачей, и её слышат все, кто слышит вас.
4. Только для этой проверки игра возвращает запись вам, и компаньон её проигрывает. Настройка «Глушить эфир, пока говорю» её не глушит: во время проверки клавиша рации не нажата.
5. Через две секунды после последнего кадра окно показывает результат: прозвучал ли тон («Тон»), самый громкий уровень микрофона («Пик микрофона»), сколько кадров отправлено и сколько вернулось и через сколько миллисекунд вернулся первый из них («Первый возврат через … мс»).

Итог проверки — один из следующих: «завершена.» (всё работает); «передача запрещена.»; «не удалось открыть микрофон.» (микрофон не открылся или перестал давать звук); «звуковые кадры не вернулись.»; «компаньон занят передачей.». Итог «компаньон занят передачей.» будет, если запустить проверку, пока вы держите клавишу рации или включён открытый микрофон. Нажмёте клавишу рации во время проверки — проверка прервётся с тем же итогом.

## Сообщения в консоли

Компаньон пишет по-английски:

| Сообщение | Что значит |
| --- | --- |
| `self-update: ...` | Выводится один раз при каждом запуске: итог проверки обновлений (см. [Обновления](#обновления)). |
| `ptt-radio-companion 0.4.0 (...), listening on 127.0.0.1:34555, game at 127.0.0.1:34556` | Компаньон запущен. Два порта — это `--port` и `--game-port`. |
| `output: <устройство> (<частота> Hz, <n> ch)` | Открыто устройство вывода по умолчанию; частота и число каналов — его собственные. С `--no-playback` этой строки нет. |
| `push-to-talk key: F8` | Клавиша зарегистрирована. |
| `warning: push-to-talk key F8 not registered: ...; only open mic works` | Система не дала зарегистрировать клавишу, обычно потому, что её уже заняла другая программа. Выберите другую в `--ptt-key`. |
| `error: ...` | Компаньон не смог подготовиться к работе и остановился, например: `cannot bind 127.0.0.1:34555: ... (another companion or radio.py running?)`, `--ptt-key <КЛАВИША>: ...` или `no default output device`. |
| `--launch: starting the game without the companion` | Только с `--launch`: компаньон не смог подготовиться к работе (причина — в строке `error: ...` прямо перед этой) и запускает игру без себя. Если не запустится и игра, он напишет `error: --launch: cannot start <программа>: ...` и выйдет с ошибкой. |
| `warning: no ROSTER from the game at 127.0.0.1:34556: ...; still trying` | Игра не ответила за 3 секунды; за один запуск это пишется один раз. В главном меню это нормально; если и после входа в сетевую игру не появилась строка `roster:`, см. [Если не работает](RU-Troubleshooting). |
| `roster:` и строки `player N  Имя  rgb(...)` | Игра ответила, это список игроков. При изменениях он выводится заново. |
| `warning: ignoring a packet that is not ptt-radio protocol v1 (mod version mismatch?)` | Игра прислала пакет, который компаньон не понимает, обычно потому, что мод и компаньон из разных релизов. Пишется один раз, на первом таком пакете; следующие только подсчитываются. |
| `open mic on (you are player N)` / `open mic off (you are player N)` | Игра сообщила, включён ли открытый микрофон. Первое состояние выводится всегда, даже `off`, а дальше — при каждом изменении. |
| `half-duplex on` / `half-duplex off` | Настройка «Глушить эфир, пока говорю» отличается от того, что сейчас у компаньона. Компаньон стартует с `on`, как и настройка по умолчанию, поэтому при настройке по умолчанию строки нет. Если вы её выключили, `half-duplex off` появится, когда игра впервые свяжется с компаньоном, а потом строка будет при каждом переключении. |
| `ptt pressed` / `ptt released` | Клавиша рации нажата или отпущена. |
| `sent START` / `sent STOP` | Передача началась или закончилась. |
| `input: <устройство> (<частота> Hz, <n> ch)` | Компаньон открывает это устройство ввода. Строка появляется при каждой попытке, если системный микрофон по умолчанию найден и его настройки прочитаны, обычно прямо перед `mic opened` или `mic open failed`. Если микрофона по умолчанию нет или его настройки прочитать не удалось, будет только `mic open failed`. |
| `mic opened` / `mic closed (...)` | Компаньон открыл или освободил само устройство ввода (микрофон). |
| `mic open failed: <ошибка>; retrying in 1 s` | Микрофон не открылся. Компаньон пробует снова раз в секунду, пока передача разрешена. |
| `game started (pid N)` / `game exited (...)` | С `--launch`: игра запущена или завершилась, и компаньон завершает работу. |
| `self-test N: Ok, tone 1, mic peak -12 dBFS, sent 150 returned 150 frames, first return 80 ms` | Проверка рации закончилась; тот же результат уходит в окно игры. |
| `self-uninstall: ...` | Мода нет, и компаньон удалил свою папку, либо что-то было неясно, и он ничего не удалил. |
| `stats: sent N frames \| received [...] \| ...` | Выводится при выходе: сколько отправлено и принято. |

## Особенности систем

### Windows

- **SmartScreen.** При первом запуске может появиться «Система Windows защитила ваш компьютер». Нажмите «Подробнее», затем «Выполнить в любом случае».
- **Брандмауэр.** Если Windows спросит, разрешить ли `ptt-radio-companion` доступ к сетям, разрешите. Если отказать, голос всё равно пойдёт через игру, только с большей задержкой.
- **Обновления.** Держите компаньон в папке, куда вы можете писать, например в «Загрузках» или «Документах», а не в Program Files: иначе он не сможет заменить сам себя.

### macOS

- **Gatekeeper.** Если сборка в релизе не подписана, при первом запуске macOS откажется её открыть. Зайдите в «Системные настройки → Конфиденциальность и безопасность», нажмите «Всё равно открыть» рядом с сообщением о `ptt-radio-companion` и запустите программу ещё раз. Другой способ — снять отметку о загрузке в Терминале: `xattr -d com.apple.quarantine ptt-radio-companion`.
- **Микрофон.** Когда рация впервые разрешит передачу, macOS запросит доступ к микрофону. Если компаньон запущен из Терминала, разрешение запрашивается для приложения терминала. Если вы отказали, включите его в «Системные настройки → Конфиденциальность и безопасность → Микрофон». Компаньон повторяет попытки, пока передача разрешена; если после смены разрешения доступа всё ещё нет, перезапустите его.
- **Клавиша.** Компаньон регистрирует `F8` как обычное глобальное сочетание и не просит ни универсального доступа, ни мониторинга ввода. На многих клавиатурах Mac `F8` — медиаклавиша: нажимайте `fn + F8` или включите в настройках клавиатуры «Использовать клавиши F1, F2 и др. как стандартные функциональные клавиши».

### Linux

- **Минимальные требования.** Релизной сборке нужна glibc 2.35 или новее: Ubuntu 22.04 и новее, Debian 12 и новее или дистрибутив того же возраста.
- **Звук.** Компаньон работает через ALSA. В системах с PipeWire или PulseAudio звук идёт к звуковому серверу через ALSA-плагин (`pipewire-alsa` или плагин PulseAudio для ALSA); в большинстве дистрибутивов он стоит по умолчанию. Программе нужна библиотека ALSA (`libasound2` или `alsa-lib`).
- **Клавиша работает только под X11.** В чистом сеансе Wayland глобальная клавиша не работает, хотя компаньон и пишет `push-to-talk key: F8`. Пользуйтесь открытым микрофоном или войдите в сеанс X11.
