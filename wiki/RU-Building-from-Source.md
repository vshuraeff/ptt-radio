# Сборка из исходников

В итоге вы сами соберёте компаньон и хаб и прогоните тесты мода.

## Что понадобится

- **Rust** 1.91 или новее, ставится через [rustup](https://rustup.rs). Этого требуют звуковые библиотеки компаньона (`sonora` 0.2.0) и тестовая зависимость `tract-onnx` 0.23.9, поэтому обычная сборка и любой `cargo test` идут только на 1.91 и новее. Если собирать только хаб, хватит Rust 1.88 или новее (см. [Только хаб](#только-хаб)).
- **cmake** и **компилятор C**: кодек Opus (libopus 1.6.1) собирается из прилагаемых исходников и линкуется статически, так что системный libopus не нужен.
- **Только на Linux:** пакет разработки ALSA и `pkg-config`, например на Debian или Ubuntu:

  ```sh
  sudo apt-get install build-essential cmake pkg-config libasound2-dev
  ```

- **macOS:** инструменты командной строки Xcode (`xcode-select --install`) и cmake, например из Homebrew.
- **Windows:** инструменты сборки Visual Studio для C++ и cmake.
- Для тестов мода: `lua` и `luac` в `PATH`.

## Сборка компаньона

1. Скачайте исходники:

   ```sh
   git clone https://github.com/vshuraeff/ptt-radio.git
   cd ptt-radio/companion
   ```

2. Соберите:

   ```sh
   cargo build --release
   ```

3. Готовые программы появятся в `target/release/`: `ptt-radio-companion`, `ptt-radio-hub` и `relay` — тестовый эмулятор игры. Проверьте, что всё работает: `./target/release/ptt-radio-companion --help`. Компаньон, собранный своими руками, никогда не заменяет себя релизной версией: обновляются сами только сборки со страницы релизов.

## Только хаб

Хабу звук не нужен. Всё, что касается звука и клавиатуры (звуковая библиотека, глобальная клавиша, фреймворки macOS), подключает фича `audio`, а она включена по умолчанию. Если её выключить, хаб соберётся без всего этого — например, на сервере, где нет заголовков ALSA:

```sh
cargo build --release --no-default-features --bin ptt-radio-hub
```

Получится `target/release/ptt-radio-hub`, и больше эта команда ничего не собирает. Для такой сборки нужны только Rust (1.88 или новее) и компоновщик: ни cmake, ни компилятор C для Opus, ни заголовки ALSA, ни `pkg-config` не понадобятся. `--no-default-features` выключает заодно и фичу `self-update`, так что библиотеки для скачивания и распаковки обновлений тоже не компилируются. Самообновления у хаба нет ни в какой сборке: сам обновляется только компаньон. А вот компаньон без фичи `audio` не собрать.

## Тесты

Из `companion/`:

```sh
cargo test --lib --bins
```

Интеграционные наборы запускаются по одному, тоже из `companion/` (в CI — только на Linux):

```sh
for t in bridge_repr connectivity crypto_sessions game_probe multiparty_lab netlab policy_contract policy_playout receive_order relay_hub transport_contract; do cargo test --test "$t" -- --test-threads 1; done
```

Тесты с пометкой ignore при этом пропускаются: один в `multiparty_lab` и пять в `policy_playout`. Наборы `scenarios` и `aec_gate` в этот цикл не входят, о них ниже.

Тесты мода, из корня репозитория:

```sh
luac -p mod/ptt-radio/*.lua mod/tests/*.lua
lua mod/tests/control_test.lua mod/ptt-radio/control.lua
lua mod/tests/channels_test.lua
lua mod/tests/admin_test.lua
lua mod/tests/settings_gui_test.lua
```

Они прогоняют обработчики событий мода без Factorio, но проверку в настоящей игре не заменяют.

### Сквозные сценарии

Здесь несколько компаньонов с виртуальным звуком работают с эмулятором `relay` вместо игры, и всё измеряется в реальном времени. Из `companion/`:

```sh
cargo test --release --test scenarios -- --nocapture --test-threads=1   # все транспорты, около 8,5 минуты
cargo test --release --test scenarios direct:: -- --nocapture           # только прямой UDP
PTT_E2E_VOICE=talk.wav cargo test --test scenarios -- --nocapture       # свой голос вместо синтетического у игрока A
```

Сценарии проверяют задержку от микрофона говорящего до ушей слушателя, эхо от динамиков, одновременную речь двоих, отключение чужих голосов на время своей передачи (настройка «Глушить эфир, пока говорю») и остановку пересылки звука на 500 мс посреди фразы. Модули `game`, `direct`, `hub`, `player_relay` и `fallback` прогоняют одни и те же проверки по каждому маршруту.

В `PTT_E2E_VOICE` подойдёт любой WAV: его сводят в моно, пересчитывают на 48 кГц, а затем обрезают или дополняют тишиной до длины реплики в каждом сценарии (3 с для задержки и эха, 3,5 с для одновременной речи, 7 с для остановки пересылки, 8 с для hard-cut). Пороги в проверках выставлены по замерам с синтетическим голосом, поэтому с другим голосом проверки могут не пройти.

Файлы последнего прогона лежат в `$CARGO_TARGET_TMPDIR/scenarios/<режим>/<сценарий>/aec-on/` или `aec-off/`; при обычном каталоге сборки это `target/tmp/scenarios/...`.

- `<режим>` — это `Game`, `Direct`, `Hub`, `Player` или `Fallback`, по модулям выше (`player_relay` пишет в `Player`). Отдельный тест `hard-cut` вместо них пишет в `CutHub`, `CutGame` и `HubDown`.
- `<сценарий>` — это `latency`, `echo`, `double-talk`, `half-duplex-on`, `half-duplex-off`, `stall`, `hard-cut` или `netlab`.
- `echo` и `double-talk` пишут и `aec-on/`, и `aec-off/`, `hard-cut` — только `aec-off/`, а `latency`, `half-duplex-*` и `stall` — только `aec-on/`. `netlab` пишет в `Game/netlab/aec-on/`, а тест `quality_sweep` (по умолчанию пропускается) — в `Game/sweep-<настройки>/aec-off/`.
- В каталоге каждого прогона есть `room-ir.wav`, `session.trace` и, во всех режимах, кроме `Game`, `network.trace`. На каждого игрока приходятся `<p>-mic.wav` (что он сказал), `<p>-speaker.wav` (что он услышал), `<p>.trace` и `<p>.log`. Игроков двое, `a` и `b`; третий, `c`, появляется только в режиме `Player`, где добавлен ещё один слушатель, и в `netlab`, где игроков трое.

### Лаборатории эха

Офлайн-лаборатории эхо-гейта нужны два независимых WAV-файла: моно, 48 кГц, 16 бит.

```sh
PTT_LAB_A=a.wav PTT_LAB_B=b.wav cargo test --release --test aec_gate -- --ignored --nocapture
```

Каждая строка таблицы результатов по умолчанию считается на 60 секундах звука; `PTT_LAB_SECONDS` задаёт эту длительность в секундах для основной таблицы (не меньше 20). WAV-файлы сохраняются без нормализации в `target/tmp/aec_gate/`.

Лаборатория эха для нескольких игроков запускается так: `cargo test --release --test multiparty_lab -- --ignored --nocapture`, а голоса задаются в `PTT_LAB_A`, `PTT_LAB_B` и `PTT_LAB_C`. `PTT_LAB_PATH` выбирает модель задержек: `game` (по умолчанию), `direct` (задержки в одну сторону A–B, A–C и B–C — 15, 35 и 25 мс) или `hub` (два участка пути до сервера, без игровых тиков). Полный прогон в release занимает около 5 минут.

Каждый голос — это путь к WAV-файлу с речью. Голоса из `PTT_LAB_A` и `PTT_LAB_B` должны быть не короче 10 секунд каждый, иначе тест падает с паникой; голос C может быть и короче. Рекомендуется моно 48 кГц и 30–40 секунд речи с паузами, но подойдёт любая частота и любое число каналов: каналы усредняются в моно, а звук пересчитывается на 48 кГц. Если голос короче сценария, он повторяется по кругу. Лаборатория приводит каждый голос к одному уровню, измеренному по участкам речи, так что исходная громкость не важна. WAV-файлы для прослушивания сохраняются в `PTT_LAB_OUT`, по умолчанию в `target/tmp/multiparty_lab/` (подкаталог `multiparty_lab` в `$CARGO_TARGET_TMPDIR`).

### Два компаньона без игры

Эмулятор `relay` подменяет и игру, и мод. Откройте три терминала в `companion/` и запустите в первом эмулятор на двух игроков, с открытым микрофоном у второго игрока, а в двух других — компаньоны с виртуальным звуком, второй из них «с динамиками»:

```sh
./target/release/relay --player 34556:34555 --player 34566:34565 --open-mic 2
./target/release/ptt-radio-companion --ptt-key none --mic-wav talk.wav --speaker-wav a-heard.wav --auto-ptt 4 --exit-after 8
./target/release/ptt-radio-companion --game-port 34566 --port 34565 --ptt-key none \
  --speaker-wav b-heard.wav --couple-gain-db -6 --couple-delay-ms 2 --exit-after 8
```

Эмулятор запускайте первым и дождитесь строк `playerN: ...`: HELLO, отправленный раньше, теряется, и список игроков (а с ним и `--auto-ptt`) придёт только со следующим heartbeat, через 5 секунд. В `a-heard.wav` записан голос A, вернувшийся через динамики B. Эмулятор понимает ещё `--echo N`, `--half-duplex N`, `--delay-ms`, `--jitter-ms` и `--stall-every S`. Без `--mic-wav` и `--speaker-wav` компаньоны берут настоящие устройства, так что этим же способом можно проверить два живых компаньона на одной машине.

### Полная проверка

```sh
tools/gate.sh [--twice] [каталог логов]   # из корня репозитория
```

Скрипт запускает `cargo fmt --check`, clippy по всем целям, отладочные тесты `--lib --bins` и все одиннадцать интеграционных наборов из списка выше, release-тесты `--lib`, сценарии, шаг `aec_gate`, замеры работы правил рации в реальном времени (пропускаемые по умолчанию тесты `policy_playout`), `luac -p` по моду и четыре Lua-теста. Шаг `aec_gate` идёт без `--ignored`, поэтому в нём выполняется только самопроверка метрики, а лаборатории эха требуют ваших WAV-файлов и запускаются только вручную, как показано выше. Одни сценарии занимают около 8,5 минуты, так что весь прогон проверки идёт дольше. `--twice` прогоняет сценарии второй раз, чтобы поймать нестабильные проверки, и добавляет ещё примерно 8,5 минуты.

- Логи по умолчанию пишутся в `<target>/gate/<время>/`; в `summary.txt` там код выхода и время каждого шага. Если упал хоть один шаг, скрипт завершается с ненулевым кодом.
- Упавший тест реального времени перезапускается один раз по точному имени; если перезапуск прошёл, шаг помечается как `flaky` и проверку не валит.
- Шаги реального времени (`scenarios-N`, `aec_gate` и `policy_playout`) держат `flock` на общем файле блокировки, чтобы два прогона проверки на одной машине не мерили одновременно. Больше эту блокировку никто не берёт: `cargo test`, запущенный вручную, может пойти параллельно с проверкой. Файл задаёт `PTT_REALTIME_LOCK` (по умолчанию `ptt-realtime.lock` в общем каталоге git, одном на все worktree), а `PTT_REALTIME_WAIT` ограничивает ожидание блокировки (по умолчанию 3600 секунд). Шаг, который не дождался блокировки, падает с `lock wait over`, и проверка переходит к следующему шагу.
- Вне git-репозитория задайте `PTT_REALTIME_LOCK`: иначе файл блокировки по умолчанию не откроется, и каждый шаг реального времени упадёт с `cannot open lock`.
- `tools/gate.sh` — скрипт на bash. Ему нужны `cargo`, `flock`, `lua` и `luac` в `PATH`; если чего-то нет, он завершается с кодом 2, не начав ни одного шага. На macOS `flock` ставится из Homebrew.

## Мод из исходников

Скопируйте папку `mod/ptt-radio` в папку `mods` игры под именем `ptt-radio` или сделайте на неё ссылку. В сетевой игре у сервера и у всех игроков должна быть одна и та же версия мода.
