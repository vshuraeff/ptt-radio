# Хаб

В итоге рядом с сервером Factorio будет работать хаб-ретранслятор, компаньоны игроков будут через него ходить, а по журналу хаба вы поймёте, что он зарегистрировался в игре.

## Зачем нужен хаб

Компаньон измеряет несколько маршрутов до каждого игрока и сам переключается между ними:

- **напрямую** — между двумя компаньонами;
- **через игрока-ретранслятора** — через компаньон третьего игрока;
- **через хаб**, если он есть на сервере;
- **через игру** — доступен всегда, но медленнее.

Когда два игрока не достают друг до друга напрямую, обычно из-за строгого NAT у одного из них, хаб даёт им быстрый маршрут через машину сервера. Хаб необязателен: без него голос всё равно дойдёт другими маршрутами. Какой маршрут используется, видно в подсказке к строке говорящего, например «через хаб».

Звук хаб не проигрывает, и звуковая карта ему не нужна. Для мода он выглядит как игрок 0 и подключается к Lua UDP-порту сервера через loopback. Отсюда правила запуска:

- хаб работает **на той же машине, что и сервер**, в том же сетевом пространстве имён;
- сервер запускается с `--enable-lua-udp <порт>` (см. [Настройка сервера](RU-Server-Setup));
- наружу для игроков открывается только публичный порт хаба.

## Порты

| Порт | Кто использует | Открывать в брандмауэре? |
| --- | --- | --- |
| `34197/udp` | игровой порт Factorio | да, как обычно |
| `34560/udp` | публичный порт хаба (`--public`), сюда подключаются компаньоны | да, и пробросить через NAT (UDP, не TCP) |
| `34556/udp` | Lua UDP-порт сервера (`--enable-lua-udp`, у хаба `--game`) | нет, только loopback |
| `34557/udp` | сюда мод отвечает хабу (`--receive`) | нет, только loopback |

## Запуск в Docker

Образ — `ghcr.io/vshuraeff/ptt-radio-hub` для `linux/amd64` и `linux/arm64`, теги: версия (`0.4.0`), минорная ветка (`0.4`) и `latest`. Аргументы после имени образа передаются прямо хабу.

**Сервер работает прямо на хосте.** Используйте сеть хоста, тогда `127.0.0.1` внутри контейнера — это loopback хоста:

1. Запустите сервер Factorio с `--enable-lua-udp 34556`.
2. Запустите хаб:

   ```sh
   docker run -d --name ptt-radio-hub --network host --restart unless-stopped \
     ghcr.io/vshuraeff/ptt-radio-hub:0.4.0 \
     --public 0.0.0.0:34560 --game 127.0.0.1:34556 --receive 127.0.0.1:34557
   ```

3. Проверьте журнал: `docker logs ptt-radio-hub` покажет `hub: public 0.0.0.0:34560 | game 127.0.0.1:34556 via 127.0.0.1:34557`.

**Сервер работает в контейнере.** Хаб подключается к сетевому пространству контейнера сервера. Контейнер в чужом пространстве сам порты публиковать не может, поэтому порт хаба `34560/udp` публикуется у контейнера сервера. В Docker Compose:

```yaml
services:
  factorio:
    # ваш образ сервера Factorio, запущенный с --enable-lua-udp 34556
    ports:
      - "34197:34197/udp"
      - "34560:34560/udp"   # публичный порт хаба
  hub:
    image: ghcr.io/vshuraeff/ptt-radio-hub:0.4.0
    network_mode: "service:factorio"
    depends_on:
      - factorio
    restart: unless-stopped
    command: ["--public", "0.0.0.0:34560", "--game", "127.0.0.1:34556", "--receive", "127.0.0.1:34557"]
```

Полный пример лежит в репозитории: [`docker/compose.example.yaml`](https://github.com/vshuraeff/ptt-radio/blob/master/docker/compose.example.yaml). С обычным `docker run` то же самое делает `--network container:<имя контейнера сервера>`.

Если контейнер сервера пересоздан или перезапущен, перезапустите и хаб: он остаётся в сетевом пространстве старого контейнера.

Оболочки в образе нет, поэтому `docker exec ... sh` не сработает; смотрите хаб через `docker logs`.

## Запуск из готового бинарника

1. Скачайте `ptt-radio-hub-<версия>-linux-x86_64.tar.gz` (или `-linux-aarch64` для ARM) и `SHA256SUMS` со [страницы релизов](https://github.com/vshuraeff/ptt-radio/releases).
2. Проверьте и распакуйте:

   ```sh
   sha256sum --check --ignore-missing SHA256SUMS
   tar -xzf ptt-radio-hub-0.4.0-linux-x86_64.tar.gz
   sudo install -m 755 ptt-radio-hub /usr/local/bin/ptt-radio-hub
   ```

   Бинарник статический, библиотеки ему не нужны.

3. Создайте `/etc/systemd/system/ptt-radio-hub.service`:

   ```ini
   [Unit]
   Description=ptt-radio relay hub
   After=network-online.target
   Wants=network-online.target

   [Service]
   ExecStart=/usr/local/bin/ptt-radio-hub --public 0.0.0.0:34560 --game 127.0.0.1:34556 --receive 127.0.0.1:34557
   DynamicUser=yes
   Restart=on-failure

   [Install]
   WantedBy=multi-user.target
   ```

4. Запустите: `sudo systemctl enable --now ptt-radio-hub`. Журнал смотрите командой `journalctl -u ptt-radio-hub`.

## Параметры

| Параметр | По умолчанию | Что делает |
| --- | --- | --- |
| `--public <IP:ПОРТ>` | `0.0.0.0:34560` | UDP-адрес, к которому подключаются компаньоны и через который идёт ретрансляция. |
| `--game <IP:ПОРТ>` | `127.0.0.1:34556` | Lua UDP-адрес сервера: порт из `--enable-lua-udp` сервера. |
| `--receive <IP:ПОРТ>` | `127.0.0.1:34557` | Локальный адрес, на который мод отвечает хабу. Этот порт хаб сообщает моду сам. |
| `--grant-ttl-s <СЕКУНДЫ>` | `1800` | Сколько живёт одно разрешение на ретрансляцию между двумя игроками. |
| `--player-grants <N>` | `64` | Сколько действующих разрешений может быть у одного игрока. |
| `--player-rate <БАЙТ/С>` | `65536` | Сколько байт в секунду хаб отправляет за одного игрока. |

Все адреса — это IP-адреса с портом. `localhost` и имена хостов не подходят.

## Что сказать игрокам

Каждый игрок запускает компаньон с адресом хаба: тот же адрес сервера, к которому он подключается в игре, и публичный порт:

```sh
ptt-radio-companion --hub 203.0.113.10:34560
```

Здесь тоже нужен IP-адрес, а не имя хоста. Игрокам в одной локальной сети с сервером лучше указывать локальный адрес сервера: многие роутеры изнутри не достают до собственного внешнего адреса.

Без `--hub` компаньон хабом не пользуется: у него остаются прямой маршрут, ретрансляция через игрока и путь через игру. С `--game-only` он вообще не открывает сетевых маршрутов и шлёт голос только через игру.

Какой маршрут выбрал компаньон, видно, если запустить его с `--trace <файл>`. При каждой смене маршрута к игроку в файл пишется строка:

```text
switch <игрок> Direct selected
switch <игрок> Hub { session: N } selected
switch <игрок> PlayerRelay { ... } selected
switch <игрок> Game selected
```

Каждая копия голосового кадра, отправленная по сети, — это строка `route_tx`. Одна копия всегда уходит и через игру, так что трафик через игру сам по себе не значит, что прямой маршрут не сработал.

## Работает ли хаб

Живых счётчиков у хаба нет. Итоговую строку он печатает при остановке (`docker stop`, `systemctl stop` или `Ctrl-C`):

```text
hub: forwarded N | bind replies N | signals N | refused grants N | dropped: ...
```

- `signals` больше нуля: мод связался с хабом, и хаб выдавал разрешения на ретрансляцию, то есть регистрация прошла.
- `bind replies`: сколько раз компаньоны достучались до публичного порта.
- `forwarded`: сколько пакетов хаб переслал между игроками.
- `refused grants`: сколько разрешений хаб не выдал из-за своих лимитов.

`signals 0` — нормальный результат, пока ни один игрок не запустил компаньон с сетевыми маршрутами: компаньон с `--game-only` у хаба ничего не просит.

## Если не работает

- **`signals 0`, хотя игроки с компаньонами в сети.** Сообщения хаба не доходят до мода. Проверьте, что порт `--game` у хаба совпадает с `--enable-lua-udp` сервера, что сервер действительно запущен с этим флагом и что хаб делит сеть с сервером (`--network host` или `network_mode: "service:factorio"`). Без вестей от хаба мод забывает его через 15 секунд; после перезапуска контейнера сервера перезапустите и хаб, потому что он остаётся в сетевом пространстве старого контейнера.
- **`error: cannot bind public ...` или `error: cannot bind receive ...`.** Порт на сервере уже занят, например вторым хабом. Остановите другой процесс или поменяйте `--public` или `--receive`; новый порт приёма мод узнает от хаба сам.
- **`bind replies 0` при `signals` больше нуля.** Компаньоны не достают до публичного порта: он не опубликован (в Compose смотрите `docker compose ps` у сервиса `factorio`), закрыт брандмауэром или не проброшен через NAT.
- **Игроки в одной локальной сети с сервером.** Многие роутеры изнутри не достают до собственного внешнего адреса (нет hairpin NAT). Хаб слушает `0.0.0.0`, поэтому игроки из LAN могут указать в `--hub` локальный адрес сервера.
- **Хаб перезапустили посреди игры.** Он начинает новую сессию, и все старые разрешения перестают действовать. Компаньоны заново объявляют себя и получают новые.
